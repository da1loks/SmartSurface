# ROS 2 и веб-интерфейс

Контракты ниже перенесены из технических заметок. Перед интеграцией сверяйте поля запросов и имена с исходниками текущей сборки.

## Топики

- `/cmd_vel` - `geometry_msgs/Twist`: команда линейной и угловой скорости; веб-узел публикует, мост Arduino принимает.
- `/odom` - `nav_msgs/Odometry`: мост публикует колёсную оценку положения и скорости; EKF и веб-узел читают её.
- `/joint_states` - `sensor_msgs/JointState`: состояния колёс для модели робота.
- `/scan` - `sensor_msgs/LaserScan`: драйвер лидара публикует; веб-узел и экспериментальные контроллеры читают.
- `/camera/image_raw` - `sensor_msgs/Image`: кадры камеры.
- `/camera/image_raw/compressed` - `sensor_msgs/CompressedImage`: JPEG при настроенном сжатом транспорте.
- `/tf`, `/tf_static`: связи между системами координат.

## Сервисы

`/led_control` использует `robosurface/srv/LEDControl`, `/servo_control` - `robosurface/srv/ServoControl`. Сервером описан мост Arduino, клиентом - веб-узел. Полные определения пользовательских сообщений пока не опубликованы.

## HTTP

В заметках указан порт 5000. Используйте фактический адрес и порт узла.

- `GET /`: интерфейс Nuxt; `/_nuxt/…`: ресурсы приложения.
- `GET /video_feed`: основной MJPEG-поток.
- `GET /video_feed_cracks`: обработанный поток при включённой модели.
- `GET /api/snapshot`: одиночный JPEG.
- `GET /api/status`: состояние робота.
- `GET /api/diagnostics`: диагностические данные.
- `POST /api/cmd_vel`: команда движения; в заметках описаны `vx`, `vy`, `vtheta`.
- `POST /api/emergency_stop`: остановка сценария и публикация нулевой скорости.
- `POST /api/led_color`, `/api/servo_control`: управление исполнительными устройствами.
- `GET/POST /api/crack_conf`: параметры распознавания; точный контракт нужно сверить по коду.
- `POST /api/start_sequence`, `/api/start_scan_sequence`, `/api/find_wall`: экспериментальные сценарии.
- `/api/auth/…`: сессии и пользователи, если авторизация включена.

Неизвестные API-маршруты не должны подменяться HTML страницы. Для маршрутов приложения предусмотрен SPA fallback.

## Socket.IO

Событие `telemetry` описывает состояние, положение `{x, y, theta}`, скорость, минимальное расстояние и счётчик дефектов. Событие `lidar_data` передаёт точки `{x, y, range}` и позицию робота для отрисовки. Счётчик дефектов в заметках отмечен как заготовка и не является проверенной метрикой.

Панель и сервер предпочтительно работают на одном origin. При раздельном размещении требуется явно настроить адрес API, CORS, cookies и транспорт Socket.IO.

## Видео

В режиме raw веб-узел декодирует кадр и кодирует JPEG для MJPEG. В режиме compressed готовый JPEG может передаваться без повторного кодирования. Разрешение, частота камеры, качество JPEG и частота нейросети - разные параметры и влияют на нагрузку независимо.
